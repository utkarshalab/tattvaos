# Canvas Architecture

**Display server for Utkarsha OS — x86-64 NASM, no libc, bare metal only.**

---

## 1. Core Design Principles

| Principle | Implementation |
|-----------|----------------|
| **Zero abstraction overhead** | Direct Utkarsha syscalls, inline assembly hot paths, no virtual calls in compositor |
| **Single address space, software isolation** | Generation-tagged handles, per-client bump arenas, bounded SPSC rings, RSO-verified clients |
| **Explicit sync everywhere** | Fences and timelines on every buffer; no implicit flushes |
| **Atomic commits only** | Surface state double-buffered; `commit` applies all pending changes in one frame |
| **No round trips on hot path** | Create/attach/damage/commit/frame-callback are fire-and-forget |
| **Capability-based security** | Interfaces invisible without grant; tokens from CPU entropy, keyed-hash authenticated |
| **Pluggable policy** | Built-in floating/tiling/kiosk + external `cw_policy` process (same protocol) |
| **Deterministic observability** | Trace IDs, frame timeline, protocol record/replay, conformance suite |

## 3. Memory Model

### 3.1 Arenas (Bump Allocators)
```
struct Arena { base: *u8, cursor: *u8, limit: *u8, parent: *Arena }
```
- **Per-client arena**: Created at connect, sized by trust profile quota. Freed on disconnect.
- **Per-frame arena**: Reset each frame; used for commit transactions, damage calc, render lists.
- **Global arena**: Long-lived objects (outputs, seats, global configs).
- **No free()** — only `mark()`/`rewind()` and arena destruction.

### 3.2 Handles (Generation-Tagged)
```
u32 handle = (generation << 20) | index
```
- 20-bit index → 1M objects max per table
- 12-bit generation → 4096 wraps before reuse
- **Every object access validates generation** — stale handles trap
- Separate handle tables per client + global table for server objects

### 3.3 Channels (SPSC Rings)
```
struct Ring { buf: *u8, cap: u32, head: u32, tail: u32, mask: u32 }
```
- Power-of-two capacity, `mask = cap - 1`
- Producer: client (tx) or server (rx); Consumer: server (rx) or client (tx)
- **Handle channel separate from payload channel** — handles never in message bytes
- Bounded: full → client throttled → disconnected

## 4. CWP Wire Protocol

### 4.1 Message Header (12 bytes, 4-byte aligned)
```
struct MsgHdr { obj: u32, opcode: u16, flags: u16, len: u32 }
```
- `obj`: generation-tagged handle
- `opcode`: interface-specific (generated by cwpgen)
- `flags`: `NEED_ACK`, `HAS_HANDLES`, `IS_EVENT`, `TRANSACTION`
- `len`: payload bytes (excludes header, 4-byte aligned)

### 4.2 Capability Negotiation
1. Client connects → sends `cw_display.get_caps(wanted_caps_bitmap)`
2. Server intersects with trust profile → grants subset
3. Client only sees granted interfaces; others return `ENOENT` on bind

### 4.3 Atomic Commit Transaction
```
cw_surface.commit(surface, flags=TRANSACTION)
  → server queues pending state
  → at frame boundary: all transaction surfaces applied atomically
  → frame callbacks fired, presentation feedback queued
```

### 4.4 Explicit Sync
```
struct Buffer { handle, w, h, stride, format, base, acquire_fence, release_fence, timeline }
```
- `acquire_fence`: client signals when buffer ready to read
- `release_fence`: server signals when done reading (client can reuse)
- Timeline points for multi-buffer pipelines

## 5. Renderer Interface (Backend-Agnostic)

```
struct RenderIface {
  begin_frame: fn(output: *Output, damage: *Region) -> *FrameCtx
  render_surface: fn(ctx: *FrameCtx, surf: *Surface, clip: *Rect)
  end_frame: fn(ctx: *FrameCtx) -> PresentInfo
  flush: fn()
  caps: RenderCaps  // SIMD level, planes, direct_scanout, HDR
}
```

### 5.1 Composition Order (Bottom → Top)
1. Output background (solid/color)
2. Direct scanout surface (if eligible: fullscreen, opaque, no transform)
3. Hardware overlay planes (video, cursor)
4. Standard surfaces (z-order, clipped to damage)
5. Server decorations (titlebar, borders)
6. Overlay layers (panels, lock screen, OSD)
7. Cursor (hardware plane preferred, SW fallback)

### 5.2 Damage-Driven Repaint
- Per-output damage region = union of all surface damage + cursor movement
- `render_begin` receives damage; renderer only touches dirty pixels
- Buffer-age tracking for partial updates (swap chain)

### 5.3 SIMD Dispatch
```
fn blend_scalar(dst, src, w, h, stride)
fn blend_sse2(dst, src, w, h, stride)   // 4 pixels/iter
fn blend_avx2(dst, src, w, h, stride)   // 8 pixels/iter
fn blend_avx512(dst, src, w, h, stride) // 16 pixels/iter
```
- CPU features detected at startup (`cpuid.asm`)
- Function pointers patched once; hot path is indirect call

## 6. Backend Interface

```
struct BackendIface {
  init: fn(config: *BackendConfig) -> *Backend
  deinit: fn(backend: *Backend)
  modeset: fn(backend: *Backend, output: *Output, mode: *Mode) -> Error
  flip: fn(backend: *Backend, output: *Output, buffer: *Buffer, fence: *Fence)
  vblank_wait: fn(backend: *Backend, output: *Output, seq: u64) -> PresentInfo
  hotplug: fn(backend: *Backend, callback: fn(connected: bool))
  cursor: fn(backend: *Backend, output: *Output, buffer: *Buffer, x: i32, y: i32)
}
```

### 6.1 Backend Hierarchy
| Backend | Use Case | Phase |
|---------|----------|-------|
| `headless` | Tests, CI, remote-only servers | C9 |
| `fb_linear` | Boot FB (VBE/UEFI GOP), copy or double-buffer flip | C9 |
| `native` | PCI display engine: modeset, vblank IRQ, planes, EDID | C10 |
| `remote` | Virtual outputs → RFB/CRP encoder | C26 |

### 6.2 Native Display Driver (Per Family)
```
src/backend/family/<vendor>/<family>/
  ├── modeset.asm    // CRTC/encoder/connector programming
  ├── planes.asm     // Overlay/cursor plane setup
  ├── vblank.asm     // Vblank IRQ handler, frame timestamps
  ├── flip.asm       // Page flip (atomic commit to KMS-like registers)
  ├── edid.asm       // EDID parse, mode validation
  └── ddc.asm        // I2C/DDC read
```
- **One family at a time** — chosen from deployment hardware
- Utkarsha provides PCI/MMIO/IRQ; Canvas owns display engine registers

## 8. Input Model

### 8.1 Event Flow
```
Utkarsha IRQ → ut_input.asm → InputSource → Seat → Focus/HitTest → Client Channel
```
- **Zero-copy**: Input events written directly into client's RX ring
- **Focus-gated**: Only focused/hit-tested surface receives pointer/keyboard
- **Global shortcuts**: Registered via `cw_shortcuts`, mediated by server

### 8.2 Seat
```
struct Seat {
  pointer: *PointerDevice,
  keyboard: *KeyboardDevice,
  touch: List<TouchDevice>,
  tablet: List<TabletDevice>,
  focus: *Surface,
  grab: *Grab,
  keymap: *Keymap,
  repeat: RepeatState
}
```

### 8.3 Pointer Acceleration
- Configurable profile (flat, adaptive, custom curve)
- Applied in server before hit-test → consistent feel across clients

### 9.1 Shell Roles

|------|-----------|----------|

struct PolicyIface {

- **External**: Separate process speaking `cw_policy` — same isolation as clients

## 10. Security Model

### 10.1 Trust Profiles (Loaded from `conf/profiles/`)
```
profile Trusted   { caps: ALL, quota: unlimited,   prompts: never }
profile Standard  { caps: core+shell+input+data,   quota: 64MB,   prompts: privileged }
profile Sandboxed { caps: core+shell+input,        quota: 16MB,   prompts: all }
profile Remote    { caps: core+shell+input+remote, quota: 32MB,   prompts: all }
profile Kiosk     { caps: core+shell+input,        quota: 8MB,    prompts: never }
```

### 10.2 Capability Gate
- `cw_capture`, `cw_inject`, `cw_policy`, `cw_debug`, `cw_session.lock` → **privileged**
- Gate checks: trust profile + explicit grant + audit log entry
- Server-drawn permission prompts (cannot be spoofed)

### 10.3 Isolation Guarantees
| Threat | Mitigation |
|--------|------------|
| Client reads other's pixels | Buffers owned by handle; release fence required |
| Client observes input not routed | Focus/hit-test enforced in server; no global keylog |
| Client injects input | `cw_inject` requires privileged grant + audit |
| Client forges handles | Generation check on every dispatch; RSO verifier |
| Client exhausts memory | Per-client arena quota; OOM kills only that client |
| Client stalls server | Bounded rings; slow client throttled then disconnected |

## 11. Enterprise Features

### 11.1 Multi-Seat
- Independent `Seat` objects, each with own outputs + input devices
- `seats.conf` maps devices → seats
- Session per seat, isolated client namespaces

### 11.2 Governance
```
struct Quota { max_surfaces: u32, max_buffers: u32, max_memory: u64, rate_msg_per_sec: u32 }
```
- Enforced at channel write; exceeded → `ENOSPC` error object
- Watchdog: ping/pong; unresponsive client → force disconnect
- Fair scheduling: round-robin client dispatch per event loop iteration

### 11.3 Observability
- **Trace**: Per-event ID, timestamp, client, object, opcode (ring buffer, mmap-able)
- **Frame Timeline**: GPU/CPU markers per frame (composite start, flip, vblank)
- **Protocol Log**: Full message log for replay
- **Record/Replay**: Deterministic replay from `.cwprec` files
- **Metrics**: Per-client stats (frames, latency, memory, errors)

## 12. Remote Display

### 12.1 RFB over TLS (C26)
- TLS 1.3 only (no legacy VNC auth)
- Tile-based dirty detection → ZLIB/raw encoding
- Input/clipboard forwarded over same connection

### 12.2 Native CRP (C27)
- Delta encoding + adaptive codec (LZ/deflate/RLE per tile)
- Multi-viewer sharing (read-only or interactive)
- Bandwidth estimation → dynamic quality

## 13. Color Management

### 13.1 Pipeline
```
Client Buffer (sRGB/linear/HDR) → ICC/per-output transform → Linear blend → Output TRC/Gamma → Scanout
```
- sRGB baseline (no ICC = assume sRGB)
- ICC v2/v4 matrix + TRC (parsed at load)
- HDR: ST.2084 PQ / HLG metadata → tonemap to SDR output
- Linear-light blending when any surface is linear/HDR

## 16. Decision Records (Summary)

| # | Decision | Rationale |
|---|----------|-----------|
| 0001 | No libc | Bare metal, control every byte |
| 0002 | Pixel format: BGRX/BGRA premul | GPU-native, blend-friendly |
| 0003 | Wire protocol: binary, versioned, handles separate | Zero-copy, no parsing ambiguity |
| 0004 | Generation-tagged handles | Stale handle safety in single AS |
| 0005 | One server, pluggable policy | Avoid WM/compositor split races |
| 0006 | Explicit sync in v1 | No implicit flush races, frame-perfect |
| 0007 | Trust profiles | Capability grants auditable, revocable |
| 0008 | Software isolation on Utkarsha | Hardware domains not yet exist |
| 0009 | Utkarsha owns buses, Canvas owns display engines | Clean driver boundary |
| 0010 | One GPU/display family at a time | Scope control, direct scanout recovers 80% benefit |
| 0011 | Defer AVIF, HEIF, and JPEG XL decoding | Prioritize required display-server features; retain accurate format detection |
